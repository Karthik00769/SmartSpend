# SmartSpend V2: Complete Software Engineering Standards

> [!IMPORTANT]
> This document serves as the permanent technical constitution for SmartSpend V2. It is the single source of truth for architectural, financial, and engineering decisions. No feature, module, or code commit may violate these standards.

---

## 1. Domain Model

Every business entity in the system is defined below.

### Core Financial Entities
* **Expense**: 
  * **Purpose**: Records a financial outflow. 
  * **Relationships**: Belongs to `User`, `Category`. Creates `LedgerEntry`. 
  * **Lifecycle**: Pending (Upload) -> Validated -> Stored -> Summarized. 
  * **Rules**: Must be > 0. Date cannot be future.
* **Budget**: 
  * **Purpose**: Spending limit for a category per month. 
  * **Relationships**: Belongs to `User`, `Category`. 
  * **Lifecycle**: Active for current month, archived historically. 
  * **Rules**: Reset monthly. Cannot be negative.
* **Goal**: 
  * **Purpose**: Savings target over a specified time. 
  * **Relationships**: Belongs to `User`. 
  * **Lifecycle**: Active -> Reached | Failed. 
  * **Rules**: Target Date must be in the future.
* **Category**: 
  * **Purpose**: Classification bucket for expenses. 
  * **Relationships**: Belongs to `User` (or System). 
  * **Rules**: System categories cannot be deleted. User categories belong strictly to that user tenant.
* **LedgerEntry**: 
  * **Purpose**: Immutable record of financial mutation. 
  * **Relationships**: Polymorphic to `Expense`. 
  * **Rules**: Cannot be updated. Corrections require a reversing entry.

### Operational Entities
* **Merchant**: Normalized payee name. Resolves from raw OCR/Bank data.
* **Receipt / Statement**: Raw files mapped to an S3 URI.
* **OCRJob / AIJob**: Background worker tasks tracking completion/failure.
* **Insight**: Actionable text generated by AI derived from aggregated data.
* **Notification**: In-app or push alerts (e.g., Budget exceeded).
* **AuditLog**: Immutable record of user/system actions (login, delete).
* **RecurringExpense**: Template object that generates `Expense` objects on a Cron schedule.
* **UserPreference / Settings**: JSON object of user UI and notification toggles.
* **Formula / Rule**: Hardcoded constants/functions in the Financial Core.
* **ConfidenceScore**: Metadata determining if human review is needed.
* **Event**: Asynchronous payload emitted during state changes.
* **Metadata**: Key-value telemetry attached to entities.

## 2. Canonical Data Model

No module may invent ad-hoc representations. All APIs and functions must consume the canonical object.

### Canonical Expense Example
- **Required**: `id` (UUIDv7), `tenantId` (User UUID), `amountPaise` (Int), `dateISO` (String), `categoryId` (Int), `createdAt` (UTC), `updatedAt` (UTC).
- **Optional**: `merchantId`, `description`, `receiptUrl`, `upiRef`, `gstin`.
- **Derived**: `isoWeek`, `month`, `year`, `financialYear`.
- **Immutable**: `amountPaise`, `dateISO` (Editing requires appending a contra-entry).
- **Validation**: Strict Zod schemas in `lib/finance/validation`.
- **Storage**: Stored in MySQL.
- **Serialization**: Converted to `amountINR` (Float) ONLY at the UI boundary.
- **Versioning**: Contains `schemaVersion` (e.g., `v2.0`).

## 3. Folder Architecture

The permanent folder structure enforces boundaries.

* **`app/api/`**: 
  * **Purpose**: HTTP edge layer. 
  * **Forbidden**: Direct DB queries. 
  * **Allowed**: Calling Services and Event Emitters.
* **`lib/finance/`**: 
  * **Purpose**: The absolute Financial Core. 
  * **Forbidden**: DB imports, HTTP imports. 
  * **Allowed**: Pure math, regex, types.
* **`services/`**: 
  * **Purpose**: Database I/O and orchestration. 
  * **Allowed**: DB imports, `lib/finance` imports.
* **`workers/`**: 
  * **Purpose**: Asynchronous job handlers (BullMQ/Inngest).
* **`components/`**: 
  * **Purpose**: React UI. 
  * **Forbidden**: Direct DB queries.

## 4. API Standards

- **Request/Response Format**: JSON only. 
  `{ success: boolean, data?: T, error?: string, code?: string, meta?: PaginationMeta }`
- **Pagination**: Offset/Limit for tables, Cursor-based for infinite feeds.
- **Filtering/Sorting**: Passed via query params `?sort=-amount&filter[category]=4`.
- **Versioning**: via URL `/api/v2/expenses`.
- **Idempotency**: `Idempotency-Key` header required for `POST` mutations.
- **Status Codes**: 200 (OK), 201 (Created), 202 (Accepted Async), 400 (Validation), 401 (Auth), 403 (RBAC), 404 (Not Found), 429 (Rate Limit), 500 (Internal).
- **Rate Limiting**: Redis Token Bucket (e.g., 100 req/min).
- **Timeouts**: APIs must respond in < 500ms. Long tasks return 202.

---

## 5. Validation Standards

**Philosophy**: Validation occurs at the boundary. Invalid data never enters the core.

- **Amount**: Min 100 Paise (₹1). Max 1,000,000,000 Paise (10 Crore). Cannot be Negative/NaN.
- **Date**: Must be valid `YYYY-MM-DD`. Expense cannot be future.
- **Receipt/Bank**: Must check magic bytes (MIME type). Max 10MB.
- **UPI / GST / Reference**: Strictly format-checked via Regex. Dropped if invalid (do not crash).
- **Duplicate Detection**: SHA-256 hash of `(userId, amount, date, merchant)` within 60s window.
- **Ordering**: Shape -> Type -> Domain Rules -> DB Constraints.
- **Error Messages**: Must be human-readable and actionable.

## 6. Financial Formula Bible

All math must use Integers (Paise) to prevent floating-point drift.

1. **Budget %**: `(SpentPaise / AllocatedPaise) * 100` (Cap at 999%, guard against Division by 0).
2. **Goal %**: `(SavedPaise / TargetPaise) * 100`.
3. **Savings Rate**: `MAX(0, ((Income - Expense) / Income)) * 100`.
4. **Average Spend**: `TotalSpent / DaysElapsed` (Current Month) or `TotalSpent / DaysInMonth` (Past Months).
5. **Monthly Growth**: `((CurrentMonth - LastMonth) / LastMonth) * 100`.
6. **Remaining Budget**: `MAX(0, Allocated - Spent)`.
7. **Spending Velocity**: `(Spent / DaysElapsed) * TotalDaysInMonth`.

## 7. AI Architecture

**AI Flow**: `Rule Engine` -> `Local ML` -> `LLM (Gemini)` -> `Confidence Score` -> `Human Confirmation`.

- **AI MAY NEVER**: Modify money, calculate balances, change the ledger, or validate financial logic.
- **AI MAY**: Categorize text, generate text summaries, coach the user, or estimate confidence.
- **Determinism**: Everything deterministic must remain deterministic. AI is strictly a "suggestive" layer.

---

## 8. Database Standards

- **Naming**: `snake_case` for tables and columns. Plural tables (`expenses`).
- **Indexes**: Compound indexes on frequent query paths `(user_id, deleted_at, expense_date)`.
- **Foreign Keys**: Enforced on all relations. `ON DELETE RESTRICT`.
- **Soft Delete**: `deleted_at` timestamp. Records are never `DELETE`d.
- **Ledger**: Immutable table. To fix a mistake, insert a negative adjustment row.
- **Migrations**: Declarative (Prisma/Drizzle). Rollbacks must be defined.

---

## 9. Logging Standards

- **Never Logged**: Passwords, Auth Tokens, Raw S3 URLs, Unmasked PII, Exact Financial Balances.
- **Always Logged**: Action Type, User ID, Resource ID, IP Hash, Timestamp.
- **Correlation IDs**: `X-Request-Id` must be passed from API to DB to Background Worker.

---

## 10. Background Workers

Heavy tasks MUST run asynchronously.
- **Jobs**: OCR Extraction, PDF Parsing, AI Insight Generation, Nightly Cron (Budgets/Goals).
- **Architecture**: Redis-backed queue (BullMQ/Inngest).
- **Retries**: Exponential backoff (3 attempts).
- **DLQ**: Failed jobs move to Dead Letter Queue for engineering review.

---

## 11. Security Standards

- **Auth/AuthZ**: JWT with Zero-Trust database `session_version` validation.
- **Encryption**: AES-256 for sensitive profile data. TLS 1.3 in transit.
- **Secrets**: Vault / AWS Secrets Manager. Never in `.env` code.
- **Rate Limiting / CSRF**: Mandatory on all mutating endpoints.
- **File Uploads**: Files uploaded directly to S3 via Pre-Signed URLs. Node server never holds the file. ClamAV virus scanning on bucket upload.

---

## 12. Performance Standards

- **Max Response**: API < 500ms. DB Queries < 50ms.
- **Query Limits**: No unbounded `SELECT *`. Mandatory `LIMIT 100`.
- **Memory**: Max 512MB per serverless invocation. Large arrays must be processed via Streams, not `.map()`.
- **Caching**: Dashboard historical queries cached in Redis for 24 hours. Invalidated on new expense.

---

## 13. Testing Standards

- **Unit Testing**: 100% coverage required for `lib/finance/*` (Formulas, Dates, Validation).
- **Integration Testing**: API to DB flow tests.
- **E2E Testing**: Playwright tests for critical user journeys (Login -> Upload Receipt -> Check Dashboard).
- **Financial Accuracy**: Dedicated fuzz testing to ensure 10 Crore amounts don't overflow the DB `DECIMAL` limits.

---

## 14. Coding Standards

- **Naming**: `camelCase` variables, `PascalCase` classes/components, `UPPER_SNAKE` constants.
- **Complexity**: Maximum function length: 50 lines. Cyclomatic complexity < 10.
- **Error Handling**: Use explicitly typed `Result<T, E>` or `try/catch` with central error formatting. Never throw generic strings.
- **Dependency Injection**: Services must receive the DB connection as a parameter to allow mocking in tests.

---

## 15. Event Architecture

Domain events decouple the system.

- **ExpenseCreated**: `Producer`: API. `Consumer`: Budget Service, Notification Service.
- **BudgetExceeded**: `Producer`: Cron/Budget Service. `Consumer`: Notification Service.
- **ReceiptProcessed**: `Producer`: OCR Worker. `Consumer`: Websocket/API.
- **Idempotency**: All consumers must ensure processing an event twice does not double-charge or double-notify.

---

## 16. Future SaaS Architecture

SmartSpend V2 is built for enterprise scale.

- **Multi-tenancy**: Every DB query must include `WHERE tenant_id = ?`.
- **Quotas**: Redis counters tracking monthly AI Insights limits and OCR limits.
- **Billing**: Razorpay integration for Pro subscription tiers.
- **Feature Flags**: LaunchDarkly/PostHog for gradual rollouts.
- **Monitoring**: Datadog/Sentry for APM, Error tracking, and SLO monitoring.
